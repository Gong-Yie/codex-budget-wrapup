# 收尾交接

用在两种时候：用量快撞限额了，或者你打算关掉这个会话。

## 先看额度

```bash
py -3 "$PLUGIN_ROOT/hooks/budget_wrapup.py" --check
```

不想跑脚本就看 Codex 的 `/status`。

## 总结写五段，不写别的

1. **目标** —— 这个会话原本要做什么，一句话。
2. **已完成** —— 实际改了什么，带路径；没做的别写进来。
3. **当前状态** —— 现在能跑吗；测过什么；明确列出没测的。
4. **未完成** —— 卡在哪，下一步第一件事是什么，具体到文件和函数。
5. **未提交改动** —— `git status --short` 还留着什么。

## 落盘

默认写进 `<cwd>/.codex-wrapup/wrapup-YYYYMMDD-HHMMSS.md`。用户指定了别的位置就按用户的。

写不了文件（只读模式、沙箱拒绝）时，把完整总结贴在回复里，不要吞掉。

## 收尾后

- 不要把没验证过的东西写成「已完成」。
- 不要在总结之后继续开新任务——额度就是为这个准备的。
- 下一轮接手的人只看这份文件就该知道从哪下手。
